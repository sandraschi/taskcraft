Local-first issue tracker for a small team, with git commit linking. One SQLite file, one binary that is both CLI and MCP server. Part of the back-office craft suite (replaces Linear / Jira / Asana for the 1-10 person case).

Status: v0.1.2, Tier 1 (store + CLI + MCP, tested). No desktop window yet. Synthetic demo data only; not used on a real team yet.

  • How to use it day to day: HELP.md
  • What it is for and where it stops: docs/PRD.md
  • Every MCP tool: docs/TOOLS.md (generated, checked by a test)
  • Changes: CHANGELOG.md

What it does

  • Projects with a short key; issues numbered KEY-n per project.
  • Status lanes: backlog, todo, in_progress, in_review, done, canceled. Priority low..urgent, story points, assignee, labels, due date, milestones with progress.
  • Relations: blocks (cycle-checked), relates_to, duplicates. Starting or finishing a blocked issue is refused unless forced.
  • Full per-issue history (who changed what, including agents, git and other craft apps).
  • git-sync: reads the project repo's git log, links commits that mention KEY-n, closes issues on closes/fixes/resolves KEY-n. Idempotent.
  • Inbox: ticket.escalated from deskcraft and contract.deadline from contractcraft become issues automatically.
  • Inbox: capacity.changed from teamcraft is stored per ISO week and shown in status (available team hours).

Quick start

taskcraft demo-seed                  # labelled demo project BC (empty DB only)
taskcraft board BC
taskcraft new BC "Fix CSV export" --priority high --labels bug,export --estimate 2
taskcraft link BC-4 blocks BC-5
taskcraft move BC-5 in_progress      # refused: blocked by BC-4, BC-6
taskcraft project create TC "TaskCraft" --repo D:\Dev\repos\taskcraft
taskcraft git-sync TC --allow-path D:\Dev\repos\taskcraft
taskcraft --json show BC-5

Database: --db PATH, else $TASKCRAFT_DB, else %LOCALAPPDATA%\taskcraft\taskcraft.db.

Product Requirements & Architecture Specification

What it is

A local-first issue tracker for a 1-10 person team (Linear / Jira / Asana replacement for the small case), with git commit linking and inputs from the other back-office craft apps. Pure Rust, ArtCraft pattern. Suite plan: BACKOFFICE_CRAFT_SUITE.md, section 4.2.

Users

  • Sandra and a small team planning work per repo or project.
  • Agents over MCP: create and triage issues, move them, link commits. Every agent change is in the history with actor agent.

Jobs

1. Keep one honest list of work per project, with priorities, estimates and due dates.

2. Make blockers impossible to ignore.

3. Connect work to commits without a hosted service.

4. Collect work that other apps discover (support escalations, contract deadlines).

Today (v0.1.1)

  • Projects with keys, KEY-n issues, statuses, priorities, points, labels, assignee, due date, milestones with progress.
  • Relations with a cycle check on blocks; moving a blocked issue to in_progress / in_review / done needs force.
  • Full per-issue history (agent, user, git:<author>, bus:<app>).
  • git-sync: read-only git log, mention linking, explicit closing keywords, idempotent.
  • Inbox: ticket.escalated (deskcraft) and contract.deadline (contractcraft) become issues; capacity.changed (teamcraft) is shown in status. All three verified end to end.
  • 17 MCP tools (TOOLS.md, generated and test-checked), CLI with board view.

Boundaries

  • No hosted sync, no GitHub/GitLab issue sync in v1 (gitops-mcp covers GitHub).
  • Git is read-only; taskcraft never writes to a repo.
  • No time tracking (teamcraft) and no customer communication (deskcraft).

Gaps (honest)

  • No egui window; the board is CLI text and JSON.
  • No comments or attachments on issues.
  • No sprints / cycles; capacity is shown, not planned against.
  • Git sync on demand only (no hook or watcher).
  • Synthetic data only.

Next

1. egui app: board lanes, issue detail with history, milestone burn-up.

2. Comments on issues.

3. Use teamcraft capacity in milestone planning.
